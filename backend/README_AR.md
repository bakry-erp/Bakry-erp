# Bakry ERP API — المرحلة الأولى لنظام المنشآت والتراخيص

## الحالة

هذه النسخة تضيف أساسًا برمجيًا متعدد المنشآت، وأكواد تفعيل، واشتراكات، وحسابات موظفين، وصلاحيات، وواجهات مزامنة مقيّدة بمعرّف المنشأة.

**هذه ليست شهادة بأن النظام أصبح متصلًا أو منشورًا.** لم يتم تشغيل ترحيل قاعدة البيانات، ولم يتم الاتصال بقاعدة Render الفعلية، ولم يتم ربط واجهة `IndexedDB` بمزامنة API في هذه المرحلة. يظل التخزين المحلي الحالي هو المصدر المستخدم في الواجهة إلى أن تكتمل مرحلة ربط العميل واختبارها.

## متطلبات التشغيل

- Node.js 20 أو أحدث.
- PostgreSQL.
- متغيرات Render الموجودة: `DATABASE_URL` و`ADMIN_USERNAME` و`ADMIN_PASSWORD` و`JWT_SECRET`.
- `APP_ORIGIN` يجب أن يكون أصل GitHub Pages فقط، دون مسار `/Bakry-erp`، مثل `https://bakry-erp.github.io`.
- لا تضع أي قيمة سرية داخل ملفات الواجهة أو مستودع GitHub.

## قاعدة البيانات — مهم قبل النشر

ملف `schema_subscription_v1.sql` ترحيل إضافي مستقل. لا تشغّله على قاعدة البيانات الحقيقية قبل:

1. أخذ نسخة احتياطية كاملة والتحقق من إمكانية استعادتها.
2. فحص الجداول والبيانات الموجودة فعليًا.
3. تحديد المنشأة المالكة للسجلات القديمة.
4. الحصول على موافقة صريحة على تنفيذ الترحيل.

الترحيل لا يحذف سجلات `app_records` ولا ينسبها تلقائيًا لأي منشأة؛ يترك `tenant_id` فارغًا. بعد مراجعة البيانات، توجد نقطة API إدارية تتطلب تأكيدًا صريحًا باسم `ASSIGN_NULL_TENANT_RECORDS` لنقل السجلات القديمة إلى منشأة محددة. لا تستدعِها قبل التأكد من أن جميع السجلات القديمة تخص هذه المنشأة.

## المسارات المتاحة في هذه المرحلة

### المالك

- `POST /api/auth/login` — دخول المالك باستخدام `ADMIN_USERNAME` و`ADMIN_PASSWORD`.
- `POST /api/owner/activation-codes` — إنشاء كود تفعيل. يتطلب `duration` و`userLimit` صراحة. مدد الاشتراك: `month_1`, `month_2`, `month_4`, `year_1`, `lifetime`.
- `GET /api/owner/activation-codes` — عرض الأكواد وحالاتها دون إظهار الكود السري نفسه.
- `GET /api/owner/tenants` — عرض المنشآت والتراخيص وعدد الموظفين.
- `POST /api/owner/tenants/:tenantId/suspend` — إيقاف منشأة.
- `POST /api/owner/tenants/:tenantId/extend` — تمديد الاشتراك.
- `POST /api/owner/tenants/:tenantId/user-limit` — ضبط حد الموظفين لرقم موجب أو `"unlimited"`.
- `POST /api/owner/activation-codes/:codeId/cancel` — إلغاء كود لم يُستخدم بعد.
- `POST /api/owner/tenants/:tenantId/adopt-legacy-records` — نقل السجلات القديمة غير المنسوبة، ويتطلب `{ "confirm": "ASSIGN_NULL_TENANT_RECORDS" }`.

### المنشأة والموظفون

- `POST /api/license/activate` — استخدام الكود وإنشاء المنشأة وحساب Admin الأول. يلزم `code`, `tenantName`, `adminUsername`, `adminPassword`.
- `POST /api/auth/tenant-login` — دخول موظف المنشأة باستخدام `tenantSlug`, `username`, `password`.
- `GET /api/auth/me` — بيانات المستخدم والمنشأة الحالية.
- `GET /api/users` و`POST /api/users` و`PATCH /api/users/:userId` — إدارة حسابات الموظفين للـ Admin.
- `GET /api/license/status` — حالة الترخيص للتوكن الحالي.

### البيانات والمزامنة

- `GET /api/stores/:store` — قراءة سجلات المنشأة فقط.
- `POST /api/sync/batch` — استقبال دفعة عمليات مع `operation_uuid` لمنع التكرار و`base_revision` لكشف تعارض التعديلات.
- عند وجود تعارض يرجع الخادم `409 sync_conflict` ولا يعتمد أي عملية من الدفعة المتعارضة؛ على العميل الاحتفاظ بالعمليات المحلية وحل التعارض قبل الإعادة.
- تشمل استجابة القراءة `deleted_at` حتى يتمكن عميل المزامنة لاحقًا من معالجة الحذف المنطقي.

## سياسة الاشتراك والقرارات غير المحسومة

- مدد الشهر والشهرين والأربعة أشهر تدعم إما `calendar` أو `30_days`، ولا يقبل الخادم إنشاء كود شهري دون تحديد السياسة.
- اشتراك السنة يحسب 12 شهرًا تقويميًا. الاشتراك الدائم بلا تاريخ انتهاء.
- `userLimit` مطلوب عند إنشاء كود: رقم موجب، أو النص `"unlimited"` إذا تقرر أن عدد الموظفين غير محدود. الخادم لا يخمّن قرار الباقة. إضافة الموظفين تُنفذ داخل معاملة مع قفل صف الاشتراك لمنع تجاوز الحد بطلبات متزامنة.
- التجربة 3 أيام يجب أن تظل بياناتها محلية في IndexedDB. لم يتم تشغيل مؤقت التجربة في الواجهة بعد؛ كما أن حفظ المؤقت محليًا وحده لا يمنع التحايل بمسح بيانات المتصفح.
- فترة السماح Offline وسياسة التحقق الدوري تحتاجان ربطًا واختبارات من جهة العميل قبل اعتماد سياسة تمنع الوصول.

## الاختبارات

من داخل مجلد `backend`:

```bash
npm install
npm test
npm start
```

اختبارات `npm test` الحالية تغطي حساب نهاية مدة الاشتراك وتقويم الشهور الكبيسة ونهاية الشهر. لا تغني عن اختبارات التكامل مع PostgreSQL أو اختبار تشغيل الواجهة.

## النشر

لا تنشر هذه النسخة قبل مراجعة ترحيل SQL، وتشغيل اختبارات قاعدة بيانات على نسخة تجريبية، وربط الواجهة بعنوان API، واختبار الدخول والصلاحيات والمزامنة والاستعادة من النسخة الاحتياطية. نقطة `/api/health` تتحقق من اتصال قاعدة البيانات وتعرض أيضًا `subscriptions_schema_ready`.
